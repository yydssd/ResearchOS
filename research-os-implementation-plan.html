At a Glance

ResearchOS is a reliable research system for technical and scientific work — not a generic chatbot and not a multi-agent role-play system. It establishes a measurable research pipeline where every important conclusion can be traced from finding to canonical source.

02

Core Invariants

Six rules that must remain true throughout implementation. Expand each for the full requirement.

2.1 Evidence and claims are different objectsSource / Evidence / Claim / Hypothesis / Decision must never merge into one generic memory object
  • Source — contains evidence.
  • Evidence — may support, contradict, qualify, or fail to support a claim.
  • Claim — a synthesized interpretation of evidence.
  • Hypothesis — a research proposition that may later motivate experiments.
  • Decision — a resolved action or judgment.
2.2 Every major factual conclusion must be traceablefinding → claim → relation → evidence → source version → location; incomplete chain = unsupported 
final finding
  → claim
  → claim-evidence relation
  → evidence
  → source version
  → identifiable source location
Hard rule

If this chain is incomplete, the finding must be marked unsupported or uncertain.

2.3 Research state is explicitChat history is never the primary research state; 14 state categories are persisted

Persistent state must include:

research run · question · subquestions · tasks · works · source versions · evidence · claims · claim-evidence relations · contradictions · hypotheses · decisions · events · budget usage

2.4 The database is the source of truthNo second full copy in a large ResearchState object; LLMs receive only a controlled context view

Use a lightweight run state:

pythonclass ResearchRun(BaseModel):
    id: str
    question_id: str
    status: RunStatus
    current_phase: str
    warnings: list[str]
    budget: ResearchBudget

Sources, evidence, claims, relations, tasks, and events are stored independently. LLM components receive only a controlled context view:

pythonclass ResearchContextView(BaseModel):
    question: ResearchQuestion
    task: ResearchTask

    relevant_sources: list[SourceVersion] = []
    relevant_evidence: list[Evidence] = []
    relevant_claims: list[Claim] = []
2.5 Prefer deterministic code over LLM calls9 deterministic responsibilities vs. 7 semantic-judgment responsibilities
Deterministic codeLLM reasoning (semantic judgment only)
DOI normalization · arXiv ID parsing · metadata matching · source deduplication · budget accounting · state transitions · graph traversal · citation formatting · schema validation question decomposition · evidence extraction · claim normalization · scope comparison · contradiction judgment · counter-search generation · research review
2.6 Evaluation starts before the full system existsEvery major capability ships with fixtures and measurable tests from day one

Do not postpone evaluation until the final phase. Each major capability should have fixtures and measurable tests when it is introduced.

03

MVP Levels

Three sequential layers. MVP-1 is the current target; later layers are built only after the earlier one passes its definition of done.

MVP-1

Evidence Research System

Question → Search → Source Verification → Evidence → Claims → Claim–Evidence Graph → Contradictions → Memo
Goal: a research memo whose major factual claims have inspectable provenance.
MVP-2

Scientific Reasoning System

+ Hypothesis Generation + Counter-search + Falsification + Research Gaps + Uncertainty Analysis
Goal: actively search for reasons its conclusions may be wrong.
MVP-3

Experiment Planning System

+ ExperimentSpec + Controls + Metrics + Budget + Go / No-Go Criteria
Goal: constrained experiment specs suitable for a Coding Agent. No autonomous execution yet.

P7 Falsification · week 4Counter-search, negative ablations, alternative explanations — attempt to disprove WEEK 4

For important claims or hypotheses: generate counter-query · search contradictory work · search negative ablations · search alternative explanations · inspect source code when relevant.

Objective

Attempt to disprove — not find additional supporting papers.

Example

Hypothesis: Spatial degradation cues improve restoration because they provide location-specific degradation information.

  • Does the gain remain under feature-only matched controls?
  • Are improvements caused by parameter count?
  • Are there negative ablations?
  • Does the effect disappear on another dataset?
  • Does the implementation actually use the claimed signal?

Confidence Model

No pseudo-precise probabilities initially. Evidence dimensions are stored separately and aggregated into one overall label.

textSource authority:          HIGH
Evidence directness:       DIRECT
Context match:             HIGH
Independent replication:   NONE
Contradictory evidence:    PRESENT

Overall:                   DISPUTED

Overall labels: HIGH MEDIUM LOW DISPUTED. Numeric calibration may be added later only if benchmark evidence supports it.

Evaluation Metrics

The six quality dimensions plus cost. Unsupported claim rate is the primary metric.

M1Citation correctness
Does the cited evidence actually support the claim?
M2Citation completeness
Are important factual claims supported?
M3Unsupported claim rate primary
unsupported major claims / all major claims
M4Source coverage
Did the system recover important manually curated sources?
M5Contradiction recall
detected known contradictions / all known contradictions
M6Traceability
Every major conclusion traceable via conclusion → claim → evidence → source.

Cost tracking

LLM calls · input tokens · output tokens · search calls · documents read · wall-clock time · estimated monetary cost.
